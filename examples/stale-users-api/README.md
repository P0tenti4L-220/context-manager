# 合成案例：Agent 反复调用旧的用户接口

项目决定新客户端使用 `/api/v2/users`，但 `legacy/` 在迁移期间仍可使用 v1。两个独立任务都在 `clients/` 中引入了 v1 调用。审计器应该定位过时规则，并且解释还有什么证据才能归因历史错误。以下是手写案例和预期产物；它们不是真实运行日志。

本案例使用早期示意格式，回执只写了 ID。按详细设计，程序只有拿到回执内容并校验后才能确认加载。[F05 规格](../../docs/features/F05-incidents.md)要求保留这个缺口，并另外准备完整的合成事件包用于验收。

1. [ADR-002](project/docs/adr/0002-users-api.md) 记录已接受决策、替代关系和兼容例外；[当前客户端](project/clients/users.py)实现 v2。[历史 ADR](project/docs/adr/0001-users-api.md)保留，历史材料不应因为包含 `v1` 字样就被删除。
2. [AGENTS.md](project/AGENTS.md) 仍然要求新客户端使用 v1；[CLAUDE.md](project/CLAUDE.md) 记录的是 v2。它们对同一任务描述不同策略，但不能据此假定同一会话同时加载了它们。
3. [case.json](case.json) 包含两个独立事件的合成记录。第一次有与快照绑定的 `observed_loaded`，第二次缺少加载信息。两次都观察到了 v1 行为；只能说第一条旧规则与行为相符、有可能影响它。第二次的原因保持未知。当前规则过时则可以独立确认。
4. [示例报告](expected-report.md)展示如何表述事实、假设与未知。[proposal.diff](proposal.diff) 只更新新客户端的旧规则，保留 `legacy/` 例外及变更路由时更新测试的约束。这个 Diff 是审阅材料。

| 变体（后续加入测试） | 改变的输入 | 期望输出 |
| --- | --- | --- |
| 当前规则正确，但未加载 | v2 指令对该任务适用；出错前有完整加载记录，可排除对应的规则版本 | 建议修发现、导入或作用范围 |
| 当前规则正确，已加载后被违背 | 有 v2 指令送入对应动作前上下文的记录；证据显示动作引入 v1 | 保留规则，建议针对新客户端加回归检查 |
| 当前规则正确，加载状态未知 | 没有加载证明，只记录到 v1 调用 | 报 `unknown`；列出还需补的材料，不声称是未加载 |
| 合法兼容 | v1 只出现在 `legacy/`，或作为禁止使用的反例 | 不报过时调用，不生成删除建议 |
| 决策未确定 | v2 决策是草稿，或两个已接受决策矛盾且无替代关系 | 询问适用需求，不给依赖其中一个答案的修改 |

从仓库根目录运行以下命令，可检查手写补丁是否与样例文件匹配。该命令不会改文件；通过不代表诊断工具或真实 Agent 行为已验证。

```sh
git apply --check --verbose --directory=examples/stale-users-api/project examples/stale-users-api/proposal.diff
```
