# 功能设计子 Agent 分工

F01–F10 各设一个设计组。每组只负责一个功能，可以同时审阅和细化现有规格。各功能的实现与本地验收按依赖推进，结果统一登记在 [执行计划](../EXECUTION_PLAN.md)。

| 设计组 | 唯一负责的功能 | 交付时重点写清 |
| --- | --- | --- |
| F01 | [工程入口与公共契约](features/F01-foundation.md) | 公共类型、校验错误、CLI 骨架与最小测试入口 |
| F02 | [证据快照与受限读取](features/F02-evidence.md) | 快照标识、读取边界、引用追溯、过期及越界案例 |
| F03 | [规则发现与静态检查](features/F03-inspection.md) | 候选范围、引用检查与工具配置对应关系 |
| F04 | [规则与决策](features/F04-rules-decisions.md) | 决策生效、冲突判定、兼容范围与待确认条件 |
| F05 | [事件与加载回执](features/F05-incidents.md) | 回执验证、事件去重、复发与未知状态的案例 |
| F06 | [本地语义 Agent](features/F06-analyst.md) | 只读工具协议、预算、候选输出和真实本地模型验收 |
| F07 | [证据核验与诊断](features/F07-diagnosis.md) | 诊断证据门槛、结论等级和对应修复方向 |
| F08 | [修复 Diff 预检](features/F08-repair.md) | 修改范围、基准快照、例外保留与临时副本预检 |
| F09 | [报告与运行产物](features/F09-reporting.md) | 报告结构、证据链接、覆盖状态及写入错误 |
| F10 | [CLI 集成与最终交付](features/F10-integration.md) | 用户入口、端到端验收和打包检查 |

## 各组交付

1. 读自己负责的规格、[公共契约](contracts.md) 和直接依赖的规格。以现有规格为起点，补齐输入输出、边界条件、验收标准和依赖接口。
2. 只更新对应的 `docs/features/Fxx-*.md`。跨功能接口或公共契约有疑问时，在交接中写出具体字段、冲突和建议，由本聊天统一协调。
3. 在 `local/design-handoffs/Fxx.md` 记录负责功能、规格路径、修改要点、上游所需接口、下游可用产物、测试输入与预期、未决问题。各组交付时提供功能 ID 与交接路径。

## 本地验收与汇总

设计组可以并行完成规格和验收用例。实现模型依据确认的规格编写代码，在本机 IDE 或终端运行测试。独立模块测试可先运行，依赖相关的用例在真实接口接通后运行。实现交接写到 `local/handoffs/Fxx.md`，附代码路径、测试命令、退出码、日志和源码摘要。以 [本地验收规范](acceptance.md) 为准。

本聊天统一核对设计交接、实际代码和本地测试证据，登记通过、待修或未执行的功能。全部功能通过后，汇总功能行为、入口、依赖、测试结果和剩余限制，再按 F10 的流程完成统一交付。
